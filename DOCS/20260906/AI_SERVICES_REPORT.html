What a call costs

TIER 1

Indicative list prices from the AiPricing configuration section, surfaced to the browser by GET /api/pricing and tallied per session by SessionCostService. These are estimates shown in the UI, not billed amounts.

Unit price per AI action

USD, indicative. One eight-second clip costs what ten regenerated images cost, and what four hundred vision calls cost — which is why Veo runs on the Lite tier and is mocked in every non-production run.

Timeout budget per HTTP client

Seconds. The per-attempt value is the one that matters: the standard resilience handler defaults it to ten seconds, and raising only the total request timeout changed nothing — every attempt still died at ten while real generative calls ran 30–90 s.

Keyed on the SHA-256 of the image bytes, scoped per backend. “Try again”, result chaining and a bulk batch all re-ask the same question — each was a fresh metered call before the decorator existed.

Sliding window, six segments, queue of two. Partitioned by NameIdentifier so one user's bulk batch cannot starve another on the same IP.

Ten slots, four in flight, two retries each with 500 ms doubling backoff. A slot that fails is marked failed; the batch continues.

Fallback that had to be named

The UI once hardcoded a single explanation for every one of these paths — “no vision model was available — configure HuggingFace:ApiKey”. A rate-limited call, a content-filter refusal and an unconfigured backend are three different problems with three different recoveries, and naming the wrong one sent people to change settings that were already fine. DescriptionFallbackReason now carries the actual reason to the browser.

Retry, circuit breaker, and where the fallback lands

TIER 2

The three resilience values are interdependent and validated at startup: TotalRequestTimeout ≥ AttemptTimeout, and CircuitBreaker.SamplingDuration ≥ 2 × AttemptTimeout. Change one without the others and the host throws on boot.

The failure mode to understand

Callers of the chat, vision and image services catch failures and substitute canned output. A broken provider therefore degrades several features at once while /health still reports green — which is exactly how a dead image provider went unnoticed until its account ran out of credit.

Where mock services are allowed

Mocks:UseMockAi is gated to the Test environment by MockAiGate. Each mock implements IMockable, and the client probes /api/diag/mock-status at start-up to render a “USING MOCK DATA” banner listing every reason. A delegating handler blocks any outbound AI call while mocks are on, so a future regression fails loudly rather than spending a live token.

Routing rules, exactly

TIER 3

Vision — per request, on the namespace

IVisionService Resolve(string? modelId)
  ollama:*                        → OllamaVisionService
  remote:azure-openai-vision      → OpenAiVisionService
  remote:gemini-vision            → GeminiVisionService (if registered)
  everything else, incl. browser:*  → AzureVisionService
A browser: id should never have reached the server at all — falling through to the default is the safe reading of an id this router should not have seen.

Image generation — one provider deep

IImageGenerationService Resolve(string? modelId)
  remote:gemini-imagen3-fast  → fast instance (if configured)
  anything else, incl. null     → GeminiImagen3Service
The indirection is kept, not collapsed into a direct dependency: it is the slot where a second provider returns. It carried a HuggingFace branch until August 2026.
