Topology and Boundaries

Two web projects whose split is the thing most likely to trip you up, ten API route groups over five test tiers with hard ceilings, and a storage schema with no foreign keys because the partition key is the boundary.

Dependency rules

RuleRationaleViolation
UI only in .Client The WASM client owns the only DI container, so a server-rendered component could not resolve ImageSessionService or the deserialized auth state. Fails review
No prerendering RenderModes.WasmNoPrerender is the only mode. InteractiveServer breaks the contract outright. Fails review
VSA beats Onion When both would apply, a feature becomes a slice. The three layer projects supply primitives, not feature homes. Fails review
Infrastructure sees no ASP.NET It is a plain SDK project, so it cannot reach IHttpContextAccessor. Named clients it registers are re-opened by name in the host to attach correlation. By construction
Centrally managed packages A PackageReference with an inline version does not build. NuGet audit runs at low, so a vulnerable package breaks the build. Build gate
Warnings are errors TreatWarningsAsErrors plus EnableTrimAnalyzer. Three deliberate IL2026 suppressions exist in Program.cs, each with a written reason. Build gate

Test capacity

CI runs two tiers, not five

The single workflow builds PoRedoImage.slnx, runs Unit and Architecture, then publishes and deploys. Integration needs Docker for Testcontainers; the two E2E tiers need a live app on :4000 plus Playwright browsers. Nothing but a local run catches a break in those three — run them before pushing anything that touches storage, auth, or a page's render path.

The mock-mode decision is resolved in the host by MockAiGate.IsEnabled(...) and passed into AddPoRedoImageInfrastructure, because Infrastructure deliberately has no ASP.NET types in scope. In mock mode each concrete mock is registered once and surfaced under both its service interface and IMockable, so the client banner can enumerate reasons without constructing the service twice.

Compact schema — keys only

Table  UserImages
  PartitionKey  string   = UserId                       (the ownership boundary)
  RowKey        string   = 32-char hex GUID, "N" format
  --------------------------------------------------------------------
  Blob  user-images/{PartitionKey}/{RowKey}             (private container)
        metadata["Tags"] = comma-joined vision tags
        lifecycle rule "expire-generated-blobs-30d"

Table  BulkPrompts
  PartitionKey  string   = "prompts"                    (literal, single partition)
  RowKey        string   = UserId                       (upsert -> one set per user)

Cache  IMemoryCache
  idem:{userId|anonymous}:{uuid}        24 h    idempotent replay body
  vision:azure-cv|ollama|openai|gemini  sliding vision result by content hash

Cache  HybridCache
  meme-templates:catalog                process  immutable DTO projection

Ids are validated by UserImageId.TryParse, which uses Guid.TryParseExact(value, "N") — that rejects braces, hyphens and every non-hex character, precisely the set that would break a blob name or a Table Storage RowKey. It replaced an ad-hoc regex that accepted any hex string up to 64 characters.

Global payload envelopes

Success        the DTO itself; no wrapper, no "data" key
Error          RFC 9457 application/problem+json from Results.Problem(...)
Auth rejection bare 401 / 403 with an EMPTY body — AddProblemDetails() is not
               registered, so there is nothing to serialize
Stream         application/x-ndjson, one BulkBatchItem per line
Image bytes    Results.File(bytes, contentType) — raw, not base64
Health         a bespoke anonymous projection; the deploy smoke test greps this
               exact shape, which is why it stays anonymous rather than becoming
               a Shared DTO the browser would never deserialize
               { Status, Duration, Entries[{ Key, Status, Duration,
                                             Description, Error }] }

Health checks registered under the ready tag: key-vault, computer-vision, openai, table-storage, imagen3. /alive runs none of them — its predicate is _ => false — because it exists purely as a liveness gate for SCRIPTS/run-e2e.ps1 and the deploy smoke test.

There is no Veo health check. Video shares Google:ApiKey with Imagen, so imagen3 covers the credential, but not the Veo model id or that model's own availability. A misconfigured Google:VeoModel surfaces only as a 422 on a real, paid request.
