Boundary rules

TIER 1

Five of these are enforced by a rule registry in PoRedoImage.Tests.Architecture, which holds a registry rather than one method per rule — so the whole ruleset costs two methods against its ceiling however many rules it grows.

Rule 01

Vertical slices beat onion layers

A new feature is a new folder under Features/ holding its endpoint, DTO and validator — not a new class in a Domain/Application/Infrastructure trio. Those three supply cross-slice primitives only.

Rule 02

All interactive UI lives in .Client

Prerendering is off deliberately: the WASM client owns the only DI container — ImageSessionService, IWebAssemblyHostEnvironment, the deserialized auth state — so a server prerender pass could not resolve those services. RenderMode.InteractiveServer breaks the contract.

Rule 03

Minimal APIs only

MapGroup plus static handler methods. No MVC controllers anywhere in the solution.

Rule 04

No magic configuration strings

Every key is a constant on ConfigKeys; prefer IOptions<T>. ConfigurationBinder.GetValue<T> is banned — it trips IL2026 under the trim analyzer, and warnings are errors. Use ConfigValue.Bool/Float/Double.

Rule 05

Async all the way

No Task.Result, no .Wait().

Rule 06

Zero waste

Dead code is deleted in the same change that orphans it. Four parallel “canonical” auth routes were removed rather than migrated to, because nothing in src/ or tests/ ever called them.

Test tiers and headroom

TIER 1

Five tiers, each with a hard method ceiling asserted by a meta-test in its own assembly. Adding a test past a ceiling breaks the build — the intent is that you consolidate rather than raise the number quietly. A [Theory] counts once regardless of how many InlineData rows it carries.

Percentage of each tier's own ceiling. Unit and Integration are the tight ones: Integration sat at exactly 50 of 50 — one test from breaking the build — until the per-rule pass/fail method pairs were folded into single theories covering both sides.

What CI actually runs

Unit and Architecture only. Integration needs Docker for the Testcontainers Azurite instance; both E2E tiers need a live app on port 4000 plus Playwright browsers. Nothing but a local run catches a break in those three — so run them before pushing anything that touches storage, auth, or a page's render path. CI does build the whole solution, so a test-only compile break is still caught.

Storage model

TIER 2

There is no relational database and no ORM. Two Azure Tables carry metadata, one Blob container carries bytes, and the “join” is the composite blob name {userId}/{imageId} — the same two values that are the table's partition and row keys.

  USER_IMAGES {
    string PartitionKey PK "userId"
    string RowKey       PK "imageId — 32-char hex GUID"
    string FileName
    string ContentType
    string Kind         "Original | Regeneration | Meme | BulkVariation"
    datetime CreatedAt
    long   SizeBytes
    datetime Timestamp  "table-managed"
  }
  IMAGE_BLOB {
    string Name         PK "userId/imageId"
    binary Content
    string ContentType  "blob HTTP header"
    string Tags         "metadata — comma-joined vision tags"
  }
  BULK_PROMPTS {
    string PartitionKey PK "literal 'prompts'"
    string RowKey       PK "userId — one row per user"
    string Name            "userId"
    string PromptText      "JSON array of exactly 10 prompts"
    datetime CreatedAt
  }
  USER_IMAGES ||--|| IMAGE_BLOB : "named by userId/imageId"
  BULK_PROMPTS ||--o{ USER_IMAGES : "same userId, no enforced key"
Why tags live on the blob

Vision tags ride as blob metadata rather than widening the table schema. They are naturally scoped to the bytes and survive a read-back without a second round trip. Values are stripped to the HTTP header grammar on the way in — commas inside a tag become semicolons.

Lifecycle

Generated blobs expire on a 30-day management policy. Both clients create their container or table on first use behind a SemaphoreSlim, and both degrade to a no-op with a warning when Storage:ConnectionString is empty — the gallery simply disappears rather than crashing the host.

The provider selection is deliberately session-only: a persisted choice could strand a user on a provider that has since been removed.
Three deliberate IL2026 suppressions

Warnings are errors solution-wide, and the trim analyzer is on. The options-binding suppression is the load-bearing one: those option types use init-only properties, which the configuration binding source generator cannot assign — enabling it silently binds every value to empty and the host fail-fasts at startup. The other two are the Razor component registration and the anonymous health payload.

Compact storage schema

TIER 3

Keys only. Every query is a partition scan or a point read — there is no secondary index and none is needed at this scale.

StorePartition keyRow key / nameAccess pattern
Table UserImages userId imageId — 32-char hex GUID PartitionKey eq '{userId}' then ordered by CreatedAt descending in memory; point read for a single image.
Blob user-images {userId}/{imageId} — the two table keys, concatenated Point read, streamed straight to the response by Results.File. Container access is None — no anonymous blob reads.
Table BulkPrompts "prompts" — a literal userId One row per user, upserted whole. The ten prompts are a serialised JSON array in a single column.
In-process caches vision:{backend}:{sha256} · idem:{userId}:{key} · meme-templates:catalog Vision 6 h; idempotency 24 h; the template catalogue is immutable for the process lifetime and held in HybridCache for its stampede protection.
Why UserImageId is a struct, not a string

The value doubles as both the Table row key and the blob name, so it must stay free of the characters those stores reject — Guid.TryParseExact with the "N" format rejects braces, hyphens and any non-hex character, which is precisely that set. Modelling it as a readonly record struct costs no allocation while making it impossible to pass a userId where an image id is expected; the two were previously both bare strings sitting next to each other in every repository signature.
