What this app actually is

PoRedoImage is a photo studio where every tool is a different AI model. You give it a picture; it looks at the picture, writes down what it sees, and then hands that description to whichever model makes the thing you asked for. The browser does the whole interface — a Blazor WebAssembly SPA that owns every interactive page and the only dependency-injection container in the solution. The ASP.NET host behind it is a Backend‑for‑Frontend, not a page server: it renders exactly one host document and then exists to hold the credentials the browser must never see. Prerendering is switched off deliberately, because a server render pass could not resolve the services that live only in the client's container.

The interesting part is what happens when a model says no. Nearly every AI call site here catches its own failure and substitutes something canned — a tag list instead of a caption, heuristic lyrics instead of written ones, a softened rewrite after a safety refusal. That is what makes the system feel robust and also what makes it hard to debug: a dead provider degrades several features at once while /health still reports green. The codebase's answer is a rule rather than a patch. Every fallback path must set a user‑facing reason — DescriptionFallbackReason, LyricsFallbackReason, RefusalReason — because silent degradation reads to the person holding the phone as "the AI ignored my photo."

At a glance

Architecture BFF + WASM

Two web projects. .Client ships to the browser and owns every interactive page; .Web hosts the API and holds the secrets. Server code is vertical‑slice, not layered.

External integrations 6 providers

Azure Computer Vision, Azure OpenAI, Google Gemini/Imagen, Google Veo, Google Lyria, and optional local Ollama. Browser and on‑device models run outside the server entirely.

Auth strategy Cookie BFF

Three startup‑resolved modes: fake‑auth headers for tests, cookie‑only when no client id is configured, Entra OIDC + cookie otherwise. Production without a client id throws.

Enforced budget 5 min

Total request timeout on the generative client — the real ceiling, since three attempts at two minutes each would otherwise reach six.

Invariant

app.UseAntiforgery() alone protects nothing on this API. It validates only what it recognises as a form post, so a JSON POST sails straight through regardless of endpoint metadata. Enforcement is the AntiforgeryValidationFilter, applied at the group level so a newly added POST inside an existing group is covered by default rather than by memory.

Error envelope — RFC 9457

Failures use ASP.NET Core's problem-details writer. The client deserializes the subset it actually reads into ProblemDetailsDto; the wire object carries more. 

// wire — application/problem+json
{
  "type":     "https://tools.ietf.org/html/rfc9110#section-15.5.1",
  "title":    "Video Generation Declined",
  "status":   422,
  "detail":   "The image was rejected by the provider's safety filter.",
  "traceId":  "00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01"
}

// PoRedoImage.Shared/DTOs/ProblemDetailsDto.cs — what the client binds
public sealed class ProblemDetailsDto
{
    public string? Title  { get; set; }
    public string? Detail { get; set; }
    public int?    Status { get; set; }
    public string? Type   { get; set; }
}

Distributed tracing conventions

KeyDirectionSet byBehaviour
X-Correlation-ID in & out CorrelationHeaderHandler (client) → RequestContextMiddleware Echoed on the response and re‑stamped onto outbound provider calls by OutboundCorrelationHandler, so one id spans browser → BFF → Gemini. Absent → fresh GUID.
X-Session-ID in & out ClientRequestContext Stable for the life of the SPA session. Falls back to HttpContext.TraceIdentifier for non‑WASM callers.
Idempotency-Key in caller, optional Must parse as a UUID or the request is rejected 400. A repeat inside the 24 h TTL replays the cached 2xx body.
Idempotent-Replay out IdempotencyKeyFilter "true" when the body came from cache rather than a fresh execution.
X-CSRF-TOKEN in AntiforgeryTokenHandler The client cannot read the HttpOnly cookie, so it echoes the token in this header. One retry on 400 is normal after sign‑in.

Serilog log-context properties

Pushed once per request and present on every entry written inside it, so a single filter reconstructs a user's whole session.

Read this before trusting /health

A green /health does not mean the AI features work. The five checks probe connectivity; the call sites catch failures and substitute canned output. Azure Computer Vision's Caption and DenseCaptions are region‑unavailable on the configured resource, so AzureVisionService falls back to joined tags on every single call while its health check reports healthy.
