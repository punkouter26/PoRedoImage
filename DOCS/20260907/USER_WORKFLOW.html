Tier 1 · Executive

What people come here to do

Every journey starts the same way — one photo, picked in the browser — and then diverges on what the user wants made out of it.

IntentRouteState it mutatesBudget
"Make this photo again, but better" /image-regeneration Session only, until the user saves to the gallery ~$0.042 · up to 5 min
"Turn this into a meme" /meme-generation Session only; compositing is local ~$0.003 · seconds
"Roast me over a beat" /rap-roast None — nothing persisted ~$0.044 · up to 5 min
"Run my photo through a board of prompts" /bulk-generate Prompt board persists to Table storage $0.039 per slot · 4 at a time
"Make it move" /video None — the clip is returned inline $0.40 · 1–5 min, polled
"Show me what I've made" /gallery Reads and deletes blobs owned by the caller storage only

Input validation, in the order it happens

Four gates, and the earlier ones exist specifically so the expensive ones are never reached with junk. Note the third: magic bytes beat the declared content type, so a .png extension on a JPEG resolves to image/jpeg and a spoofed header is simply overruled.

  • 1Kestrel caps the request body at 25 MB; the multipart form limit matches.
  • 2The client refuses files over 20 MB before encoding, matching ImageBytes.MaxSizeBytes so the round trip is never wasted.
  • 3ImageBytes.FromBase64 decodes, sniffs magic bytes, and rejects anything that is not JPEG, PNG, GIF, WebP or BMP — then re‑checks the decoded length against 20 MB.
  • 4ValidationFilter<T> runs the DataAnnotations contract: required fields, DescriptionLength in 200–500, prompts 3–1200 characters, at most 20 precomputed tags of 100 characters each.
HEIC is not accepted

The magic‑byte sniff has no HEIC branch, so an iPhone photo shared in its native format is rejected with an actionable message: "Unsupported image format. Supported types: JPEG, PNG, GIF, WebP, BMP. (On iOS, convert HEIC to JPG before uploading.)" This is the single most likely first‑run failure for a mobile user.

Journey 5 — video, the only asynchronous one

Every other feature is a single request. Video is a start‑then‑poll pair, because a render takes one to five minutes — longer than any sensible request timeout. 

sequenceDiagram
  autonumber
  participant UI as VideoGenerate.razor
  participant S as BFF
  participant V as Veo 3.1 Lite

  UI->>S: POST /api/video/generate { image, prompt }
  alt Google ApiKey not configured
    S-->>UI: 503 "Video Unavailable"
  end
  S->>V: start render
  alt provider declines
    V-->>S: 4xx + reason
    S-->>UI: 422 "Video Generation Declined"
(carrying the provider's own words)
  else provider unwell
    V-->>S: 5xx
    S-->>UI: 502 "Video Service Error"
  else accepted
    V-->>S: operations/…
    S-->>UI: 200 { operationName }
  end
  loop until Done
    UI->>S: GET /api/video/status?op=operations/…
    S->>S: reject "..", leading "/", or no "operations/"
    S->>V: poll
    V-->>S: { done: false }
    S-->>UI: { done: false }
  end
  V-->>S: { done: true, video }
  S-->>UI: { done: true, videoData, videoContentType }
Why the handle is validated

The operation handle comes from the client and reaches the provider URL as a path segment. It is therefore constrained to the shape Google issues — it must contain operations/, must not start with /, and must not contain .. — so a crafted value cannot walk the path onto a different endpoint.

  H --> I["Re-roll a slot →
POST /reroll, seeded by its prompt"]

Per‑slot failure policy. One failed generation marks its own tile Failed and carries its own ErrorMessage; the other slots complete normally. A board of twelve prompts costs twelve image generations regardless of the concurrency cap — the cap paces spending, it does not reduce it.

Tier 3 · Implementation

Request and response contracts

Every type below lives in PoRedoImage.Shared and is serialized through SharedJsonOptions.CreateResolver() on both sides of the boundary, so the client's call sites and the minimal APIs share one resolver chain. Shared must stay trim‑safe.

Image analysis

// POST /api/images/analyze — anonymous, rate-limited "ai-endpoints"
public class ImageAnalysisRequest
{
    [Required] public string ImageData   { get; set; }   // base64, or a data: URI
    [Required] public string ContentType { get; set; }   // hint only — magic bytes win
    public string FileName { get; set; }

    [Range(200, 500)]
    public int DescriptionLength { get; set; } = 200;

    public ProcessingMode Mode = ProcessingMode.ImageRegeneration;  // | MemeGeneration
    public string? ModelId          { get; set; }        // vision — AiProviderIds namespace
    public string? ImageGenModelId  { get; set; }

    // Set when the browser already did the work locally, so the server skips the vision call.
    [StringLength(4000)] public string? PrecomputedDescription { get; set; }
    [MaxCount(20)][MaxItemLength(100)]
    public IReadOnlyList<string>? PrecomputedTags { get; set; }
    public string? PrecomputedEnhancedPrompt { get; set; }
}

// 200 →
public class ImageAnalysisResponse
{
    public string  Description  { get; set; }
    public List<string> Tags    { get; set; }
    public double  ConfidenceScore { get; set; }
    public string? RegeneratedImageData { get; set; }
    public string  RegeneratedImageContentType { get; set; } = "image/png";
    public ProcessingMetricsDto Metrics { get; set; }
    public string? MemeImageData { get; set; }            // MemeGeneration mode only
    public string? MemeCaption   { get; set; }
    public string? DescriptionFallbackReason { get; set; }  // ← non-null = degraded
}

public class ProcessingMetricsDto
{
    public long ImageAnalysisTimeMs        { get; set; }
    public long DescriptionGenerationTimeMs{ get; set; }
    public long ImageRegenerationTimeMs    { get; set; }
    public int  DescriptionTokensUsed      { get; set; }
    public string? ErrorInfo               { get; set; }
    public long TotalProcessingTimeMs => sum of the three above;
}

Rap roast

The response is unusually confessional by design: seven of its fields exist only to tell the user how the result was degraded, and FilterReport exposes the refusal loop verbatim.

Validation middleware

// Features/Shared/ValidationFilter.cs — an IEndpointFilter, applied per endpoint.
// It runs BEFORE the handler, so an invalid request never reaches a paid provider.
.AddEndpointFilter<ValidationFilter<ImageAnalysisRequest>>()
.AddEndpointFilter<ValidationFilter<RapRoastRequest>>()

// Custom DataAnnotations attributes live in PoRedoImage.Shared/Validation:
[MaxCount(20)]        // collection length ceiling — bounds an untrusted array
[MaxItemLength(100)]  // per-element string ceiling

// Image guards — PoRedoImage.Shared/Imaging/ImageBytes.cs
public const int MaxSizeBytes = 20 * 1024 * 1024;   // matches the client's ImageLoadHelper

// FromBase64 order of operations:
//   1. strip a data: URI prefix (malformed → "no comma")
//   2. decode base64            (bad → "not valid base64")
//   3. sniff magic bytes        (unknown → the supported-types message)
//   4. re-check DECODED length against MaxSizeBytes
// Step 3 trusts the bytes over the content-type hint, defeating header spoofing.
