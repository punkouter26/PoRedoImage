AI Services Report

Six providers, one router per capability, and a per‑action cost spread of 400×. This report covers what each call costs, how long it is allowed to take, and — the part that matters operationally — what the user gets back when a provider says no.

Tier 1 · Executive

Providers, budgets and what they cost

Prices are the indicative list figures the app itself shows users, bound from the AiPricing configuration section. They are estimates surfaced in the UI, not billed amounts.

Per video render $0.400

Veo 3.1 Lite, 8 s at 720p — 8 × $0.05/sec. The Standard tier is eight times this, which is why Lite is the default.

Per generated image $0.039

Gemini 2.5 Flash Image, the same figure for text‑to‑image and image‑to‑image. The largest recurring charge outside video.

Per vision analysis $0.001

Azure Computer Vision. Memoised by image content hash, so a repeated upload in the same session costs nothing.

Concurrency cap 4

Simultaneous image‑model calls per bulk batch, with two retries and adaptive backoff on rate limits.

Cost projection per 1,000 completed runs

Derived by multiplying the list prices above by the calls each feature actually makes. A model, not a bill: caching, refusals and fallbacks all reduce the real figure.

Latency budgets

There is no SLA document in this repository. The enforceable contract is the timeout matrix below, and the values are interdependent: the resilience handler validates TotalRequestTimeout ≥ AttemptTimeout and CircuitBreaker.SamplingDuration ≥ 2 × AttemptTimeout at startup, so changing one without the others fails the host on boot.

The bug this matrix exists to prevent

AddStandardResilienceHandler defaults AttemptTimeout to ten seconds, and that default is per attempt. Raising only TotalRequestTimeout to five minutes changed nothing: every call still had ten seconds. Image generation and music routinely take 30–90 s, so each attempt died at 10 s, burned both retries, and surfaced to the user as "Something went wrong making your track." It broke image regeneration and bulk generate the same way. Only small, fast calls ever completed.

Each backend gets its own cache wrapper. The cache key is the image content hash, so a single shared wrapper would serve an Ollama answer to a caller who explicitly asked for Azure. Matching is on the namespace, never a model‑name prefix.

AudioRefused = true, RefusalReason set
  O-->>O: build FilterReport (attempts, rejected, rejected %)

A refusal is an expected outcome for a roast, not an error, so it drives exactly one softened rewrite. The cap exists because without it a stubborn safety filter would bill on a loop. Every attempt is recorded as it happens — reconstructing the count afterwards would make "one attempt" and "two attempts" indistinguishable.

The fallback catalogue

These are the paths that return something plausible instead of failing. Each must set a user‑facing reason; a new one that does not will fail review.

TriggerSubstituted outputReason surfaced asState
Azure CV Caption / DenseCaptions region-unavailable Tags joined into a sentence DescriptionFallbackReason every call
Vision call fails (429 is common) SceneDescriber returns the tag list unchanged DescriptionFallbackReason on failure

No music provider configured Lyrics alone — a normal local-dev state RefusalReason by design
Combined vision call fails Two independent calls, run concurrently — costs what it saved, nothing more by design
Scene detail (OCR, dense captions) fails Degraded bars, request still succeeds — enhancement only by design
Browser- or device-local inference fails Nothing. The exception surfaces verbatim LocalInferenceException, OnDeviceCaptionException deliberate
Why local inference refuses to fall back

Silently billing a user who deliberately picked a free on‑device model is a surprise charge. So both local paths break the pattern on purpose: the error reaches the user rather than a metered provider reaching their card. The web client's local path currently covers analyze image only; on Android it covers meme captions, where the photo is still described server‑side and only the caption is local.

Model identifier namespaces

Every id is namespaced by execution location, not by vendor. This is load-bearing: browser:qwen2.5-0.5b-instruct and device:qwen2.5-0.5b-instruct are the same weights under different runtimes and must never be treated as interchangeable. 

// PoRedoImage.Shared — AiProviderIds
remote:  azure-cv · azure-openai · azure-openai-vision · gemini-vision
         gemini-imagen3 · gemini-imagen3-fast · google-lyria
ollama:  vision                          // local daemon, dev only
browser: florence2-base · qwen2.5-0.5b-instruct    // WebGPU, WASM fallback
device:  qwen2.5-0.5b-instruct                     // ONNX Runtime GenAI, int4, Android

// The router matches the namespace, never a model-name prefix.
public static bool IsOllama(string? id)  => id?.StartsWith("ollama:",  OrdinalIgnoreCase) == true;
public static bool IsBrowser(string? id) => id?.StartsWith("browser:", OrdinalIgnoreCase) == true;
public static bool IsDevice(string? id)  => id?.StartsWith("device:",  OrdinalIgnoreCase) == true;

Do not re-add HuggingFace

Removed in 2026‑08. Its fal‑ai routing returned 400 for every configured model id and the account's inference credits were depleted (402) — while every caller silently substituted canned output, so nothing looked broken. That outage is the origin of the "every fallback must name a reason" rule. It must not return without an explicit decision.
