05

Spend controls in force

what stops a runaway bill

Rate limit

Sliding window, 10 requests per minute, partitioned by user id so one user's bulk batch cannot starve another on the same IP. Exceeding it returns 429. Applied to /api/images, /api/bulk-generate, /api/rap-roast.

Idempotency

An IEndpointFilter backed by IMemoryCache with a 24-hour TTL de-duplicates writes on /api/bulk-generate and /api/user-images, so a retried POST never pays twice.

Mock guardrail

MockAiDelegatingHandler sits in the HTTP pipeline of all three AI-named clients and blocks any outbound call when Mocks:UseMockAi is on. In mock mode the real clients are never resolved, so this only fires on a future regression — and fails loud rather than spending a token.

Body cap

Kestrel is bounded to 25 MB against the 20 MB client-side cap plus JSON envelope, so a 50 MB base64 payload cannot OOM the worker before it reaches a paid model.

Resilience retries

Gemini and HuggingFace clients carry a standard resilience handler with 2 retry attempts. Retries are billable — a failing upstream costs up to 3× list price per logical request.

No budget ceiling

There is no cumulative spend cap — nothing stops sustained traffic inside the rate limit from running past a monthly budget. The rate limit bounds the burst, not the total.
