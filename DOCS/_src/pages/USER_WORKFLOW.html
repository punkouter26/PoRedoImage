Onboarding & execution

what the user does, and what happens

Land on the studio

The shell and WASM runtime are served anonymously. Until the runtime hydrates the serialized principal there is no authentication state at all — the boot mask — which is why every /_framework asset must load without a cookie.

GET /AllowAnonymous shell

Get redirected to sign in

_Imports.razor applies [Authorize] assembly-wide, so AuthorizeRouteView renders RedirectToLogin for an unauthenticated visitor. Forced login is the default; pages opt out, never in.

/loginAuthorizeRouteView

Authenticate

Microsoft Entra ID via the OIDC code flow, or — outside Production only — a GUEST sign-in. Either way the result is one HttpOnly, SameSite=Strict cookie. No token ever reaches the browser: SaveTokens is false and the client receives serialized claims only.

HttpOnly cookieSameSite=Strictclaims, not tokens

Choose a feature

The studio home lists and describes every function — the top nav deliberately carries no feature links. Choosing Image Regeneration routes to a page that shares the active image through ImageSessionService, so switching features later does not lose the upload.

/image-regenerationImageSessionService

Upload an image

Held client-side and capped at 20 MB. Kestrel is bounded at 25 MB — the extra 5 MB is headroom for the base64 JSON envelope, and the bound exists so an oversized payload cannot exhaust the worker before it reaches a paid model.

20 MB client cap25 MB Kestrel limit

Pick providers, then press Regenerate

The AI service picker offers one row per capability. Selection is session-only and resets on reload, so a provider removed from the catalog can never leave a stale selection stranded. The submit calls PostAsJsonAsync("api/images/analyze", …) with a 4-minute token.

AiSelectionStatePOST /api/images/analyze

The request crosses the middleware

CorrelationHeaderHandler stamps X-Session-ID and X-Correlation-ID; the cookie flows because the call is same-origin. Server-side: request context → rate limiter (10/min per user) → antiforgery → authentication → authorization → ValidationFilter.

correlation stamped10 req/minDataAnnotations validated

The orchestrator runs the pipeline

ImageAnalysisOrchestrator resolves a vision service through the router and analyses the image, then branches on ProcessingMode: regeneration enhances the description and calls the image generator; meme generation writes captions and renders locally with ImageSharp. Per-stage timings and description tokens are collected into ProcessingMetricsDto.

VisionAzure OpenAIGeminimetrics captured

Save to the gallery

UserImageSaveService POSTs with an idempotency key, so a retried save never writes twice. The repository puts the bytes in a private blob at user-images/{userId}/{imageId} and upserts metadata into the UserImages table partitioned by user. A failure surfaces as a Radzen toast that offers a retry.

Where the payload lands

storage layout and local equivalence

Storage layout

The blob container is created with PublicAccessType.None; bytes are streamed back through GET /api/user-images/{id} rather than served from storage, so the ownership check cannot be bypassed with a direct URL.

Behaviour when storage is absent

degrades, does not crash

Both repositories accept a null client. With no connection string configured, SaveBlobAsync returns an empty string and the app keeps working — regeneration succeeds, only persistence is silently unavailable.

Local development
Defaults to UseDevelopmentStorage=true — Azurite, which the integration tier also uses via Testcontainers.
Lifetime
Both repositories are singletons: TableClient and BlobContainerClient are thread-safe, and this avoids a redundant CreateIfNotExists per request.
Worth flagging
A silent empty return means a misconfigured deployment loses saves without an error surfacing to the user. A health check already covers table storage; the blob path has no equivalent.

06

What the user sees when it fails

error surfaces along the path

Session expired

The API returns 401, never a redirect — both the cookie and OIDC handlers suppress the 302 for /api paths. The client re-renders /login rather than parsing an HTML page as JSON.

Rate limited

429 after 10 requests in a sliding minute. The partition key is the user id, so one user's bulk batch cannot starve another behind the same IP. Two requests may queue; the rest are rejected.

Provider failure

Two retries with a circuit breaker on the Gemini and HuggingFace clients. Ollama gets none — it is local, so failing fast is more useful than waiting. Persistent failure surfaces as a problem-details response.

Save failure

A Radzen toast offers a retry, holding a TaskCompletionSource per circuit. The idempotency key is reused, so the retry cannot produce a duplicate gallery entry.

Mocked services

The client probes /api/diag/mock-status anonymously at startup and renders a USING MOCK DATA banner. The probe has a 3-second timeout and swallows failures, so a slow server never blocks app start.

Unhandled error

Non-/api paths re-execute to /not-found; outside Development the exception handler routes to /Error — which inherits [Authorize], so an unauthenticated user is sent to /login instead. See report 02.
