Why CLS and memory are two charts, not one CLS is a unitless score around 0.05; the heap is tens of megabytes. Plotting them together would need two y-axes on one frame — which makes the crossings and relative slopes an artefact of where each axis was zeroed, not a fact about the data. Small multiples say the same thing without the distortion. The x-axis is shared, so they still read as one window.

The gap is specific and small: there is no client-side collector and no store. The server-side pipeline that would receive one is already built and sampled.

Sampling policy

ErrorPreservingSampler.cs
Routine spans
Sampled at a configured ratio — 10% in Production.
Error-bearing spans
Always kept when the error is known at span start: an error=true tag or an HTTP status ≥ 500.
Trace integrity
Wraps ParentBasedSampler, so a sampled-in trace keeps all of its children rather than fragmenting one operation across the sampling boundary.
The head-sampling gap
A request that throws later cannot be rescued by a head sampler. That case is covered separately: the Serilog → Application Insights sink exports every logged exception at 100%, unsampled.

Secret masking on /api/diag

DiagnosticsEndpoints.MaskValue

Twelve configuration values are exposed for diagnosis. Nine are masked; three (MinTagConfidence, the chat deployment name, and the environment) are returned in full because they are not secrets.

Empty
Returns the literal (not set) — distinguishing "absent" from "masked", which matters when diagnosing a Key Vault reference that failed to resolve.
≤ 8 characters
Fully masked — too short to reveal any prefix safely.
Longer
Keeps up to 4 leading and 4 trailing characters, capped at a quarter of the length each.
Access
Guarded by the DiagnosticsAccess policy — in Production, an email on the Diagnostics:AdminEmails allow-list. An empty list denies everyone.
04

To make this dashboard real

the missing pieces, in order

1 · Collect
A small JS module reading PerformanceNavigationTiming (load and DOMContentLoaded) and a PerformanceObserver for layout-shift. Client/wwwroot/js/ already hosts four such modules, so the pattern exists.
2 · Report
POST the sample to a new diagnostics slice endpoint. It would inherit correlation headers automatically — CorrelationHeaderHandler stamps every outbound client call.
3 · Store
Azure Table Storage is already wired and running against Azurite locally; a ClientVitals table partitioned by day would need no new infrastructure.
4 · Serve
Extend /api/diag with a history projection behind the same DiagnosticsAccess policy — then this page reads it and the banner flips to live on its own.
