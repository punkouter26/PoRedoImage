Report 06 · Testing Tiers

Four tiers, and a ceiling on each

164 tests arranged so that speed decreases and fidelity increases with each step down. Unusually, the tier sizes are not conventions — they are asserted by meta-tests that fail the build when a tier grows past its budget. One tier has almost nothing in it.

The unusual part Each tier asserts its own size. A TestCountCeilingTests class in every project reflects over the assembly and fails if the tier exceeds its budget — 100 / 50 / 25 / 25. The counting logic lives in one linked file, tests/TestCounting.cs, rather than being copy-pasted four times. The effect is that adding a slow test is a deliberate act: you must either stay under budget or justify raising it.

Rows are ordered fastest-first, so Tier 2 appears last: Azurite-backed tests are the slowest of the in-process tiers. Tiers 2 and 3 share one assembly and one ceiling of 50 — Tests.Integration holds 48 enforced tests, of which exactly 2 are [DockerFact]. Tier 4 spans two assemblies with a ceiling of 25 each: 10 API smoke and 11 UI.

The shape is not a pyramid Tier 2 contains two tests. One round-trips a bulk prompt through Table storage; one checks the Azurite health check. Everything else in the integration assembly runs against CustomWebApplicationFactory without a container. That is a defensible trade — containers are slow and the storage code is thin — but it means AzureBlobUserImageRepository, the repository behind every gallery save, has no integration coverage at all: no blob round-trip, no ownership-partition test, and no assertion that a missing connection string degrades rather than throws. That is the single largest gap in this suite.

what each layer proves

Tier 1 — Unit

95 tests · no I/O

Everything that can be decided without a network, disk or clock. The largest cluster is provider routing and the local-AI fallback chain — logic that is easy to get subtly wrong and cheap to pin down.

Routing
VisionServiceRouterTests, ImageGenerationRouterTests — proves a browser: id is never mistaken for an ollama: one
Local AI
LocalAiChainTests — dtype pruning order on devices with and without WebGPU
Agents

Contracts

Cross-page state
ImageSessionServiceCrossPageStateTests

Tier 2 — Azurite integration

2 tests · Testcontainers

One AzuriteContainerFixture serves the whole xUnit collection. Previously each class — and in one case each method — started its own azurite:latest, so container count scaled with the suite.

Docker absent
The fixture does not throw. IsAvailable stays false, the connection string stays empty, and every [DockerFact] self-skips.
Address
127.0.0.1, never localhost — which can resolve to ::1, where Azurite does not listen, producing connection timeouts on Windows and CI.
Cleanup
Five layered routes, all converging on one idempotent teardown: the Testcontainers reaper, xUnit DisposeAsync, ProcessExit, Console.CancelKeyPress (the most common accidental-leak vector in dev), and a finalizer.
Naming
Per-process container names let parallel CI shards disambiguate, and let an out-of-band prune target only this project's containers.

Tier 3 — API integration

46 tests · in-process host

Real middleware, real routing, real authorization — with AI substituted. FeatureFlags:UseRealAiInIntegrationTests defaults to false, so the suite runs against the mock ladder and spends nothing.

Hosts
CustomWebApplicationFactory for plain API tests; AzuriteWebApplicationFactory when storage is needed
Identity
TestAuthHandler — the suite authenticates without driving a login flow
Coverage
Health, diagnostics, image analysis, bulk generate, rap roast, precomputed vision, prompt round-trip, and a budget guardrail test
Budget guardrail
BudgetGuardrailTests asserts the mock handler actually blocks outbound AI calls — the regression net under the cost controls

Tier 4 — Playwright E2E

21 tests · real browser

Split across two assemblies: API smoke (HTTP against a live instance) and UI (a real browser). Both gate on [LiveServerFact].

Target
E2E_BASE_URL, defaulting to http://localhost:4000. HTTPS redirection is disabled in Development precisely so this suite sees real status codes rather than a 307.
No instance
Self-skips with a message naming the unreachable URL — a missing server never reports as a failure.
Identity
Auth:EnableFakeAuth plus X-Fake-User lets headless runs assume any identity or role without the interactive flow.
Coverage
Login journeys (6), accessibility (4), the AI service picker (1), and 10 API smoke checks. PlaywrightViewports parameterises the viewport matrix.
Isolation
Both E2E projects reference only Shared — they cannot reach into the host and are honest black-box clients.

05

Self-skipping gates

why a missing dependency is not a failure

[DockerFact]

Probes the shared Azurite fixture. No Docker daemon → IsAvailable is false → the test reports as skipped with a reason, and the body that would use the connection string never runs. A developer without Docker still gets a green Tier 1 and a truthful Tier 2 result.

[LiveServerFact]

Probes E2E_BASE_URL before the test runs. Nothing listening → skipped with "No live instance reachable at {url}". Because the UI project references the API smoke project, a single attribute governs both E2E tiers.

The trade-off this makes Self-skipping keeps local runs green and fast, but it also means a CI job that silently loses Docker or its test instance reports success while testing far less than it appears to. The counter-measure is to assert the expected skip count in CI, or fail the pipeline when a tier reports zero executed tests. Neither is present today.
