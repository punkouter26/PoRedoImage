    autonumber
    actor User as User (mobile-first browser)
    participant WASM as Blazor WASM · PoRedoImage.Client
    participant Handler as CorrelationHeaderHandler (DelegatingHandler)
    participant Kestrel as Kestrel · MaxRequestBodySize 25 MB
    participant Ctx as RequestContextMiddleware
    participant RL as UseRateLimiter · ai-endpoints
    participant AuthN as UseAuthentication · Cookie or FakeAuth
    participant AuthZ as UseAuthorization · FallbackPolicy
    participant Group as MapGroup /api/images
    participant Filter as ValidationFilter + IdempotencyKeyFilter
    participant Orch as ImageAnalysisOrchestrator (Application)
    participant Out as OutboundCorrelationHandler
    participant AI as External AI · HuggingFace / Gemini / Ollama / Azure CV
    participant Store as Azure Table + Blob (Azurite locally)

    rect rgb(232, 244, 253)
        Note over User,WASM: Boot — /_framework assets served AllowAnonymous so the WASM app can start
        User->>WASM: Navigate to /rap-roast
        WASM->>WASM: AuthorizeRouteView reads deserialized AuthenticationState
    end

    User->>WASM: Submit photo (base64, <= 20 MB client cap)
    WASM->>Handler: HttpClient POST api/rap-roast

    rect rgb(240, 248, 236)
        Note over Handler: §6.9 correlation stamping
        Handler->>Handler: X-Session-ID = ClientRequestContext.SessionId (stable per tab)
        Handler->>Handler: X-Correlation-ID = new GUID (per request)
    end

    Handler->>Kestrel: POST /api/rap-roast<br/>Cookie: HttpOnly + SameSite=Strict + Secure
    Note right of Kestrel: Cookie is attached by the browser.<br/>WASM never reads or holds a token (BFF invariant).

    Kestrel->>Ctx: pipeline hop 1
    Ctx->>Ctx: Read or generate X-Correlation-ID / X-Session-ID
    Ctx->>Ctx: Echo both on the response, store in HttpContext.Items
    Ctx->>Ctx: LogContext.PushProperty CorrelationId / UserId / SessionId

    Ctx->>RL: UseSerilogRequestLogging then UseRateLimiter
    alt Sliding window exceeded (10 req/min per user id)
        RL-->>WASM: 429 Too Many Requests
    else Within budget
        RL->>AuthN: continue
    end

    AuthN->>AuthN: Validate auth cookie, build ClaimsPrincipal
    AuthN->>AuthZ: continue
    alt Unauthenticated and path starts with /api
        AuthZ-->>WASM: 401 (ApiAwareRedirectToLogin — no 302 to /login)
    else Authenticated
        AuthZ->>Group: RequireAuthorization satisfied
    end

    Group->>Filter: RequireRateLimiting + endpoint filters
    Filter->>Filter: DataAnnotations validation -> 400 ProblemDetails on failure
    Filter->>Filter: Idempotency-Key de-dup (IMemoryCache, 24 h TTL)
    Filter->>Orch: RapRoastRequest DTO (PoRedoImage.Shared)

    Orch->>Out: ISceneDetailProvider / IChatCompletionService / IMusicGenerationService
    Out->>Out: Re-stamp X-Correlation-ID + X-Session-ID from HttpContext.Items
    Out->>AI: Azure CV Read/DenseCaptions, HF Qwen2.5-VL, Gemini, Lyria 3
    Note right of AI: MockAiDelegatingHandler blocks this leg entirely<br/>when Mocks:UseMockAi = true
    AI-->>Out: Scene facts / lyrics / audio bytes
    Out-->>Orch: results

    Orch->>Store: Persist via IUserImageRepository (Blob bytes + Table metadata)
    Store-->>Orch: UserImageId

    Orch-->>Group: RapRoastResponse
    Group-->>Kestrel: 200 OK (System.Text.Json + SharedJsonContext source-gen)
    Kestrel-->>WASM: Response + echoed X-Correlation-ID / X-Session-ID
    WASM-->>User: Lyrics, audio player, subject photo

    rect rgb(253, 240, 240)
        Note over Ctx,AI: One correlation id spans browser -> BFF -> downstream AI,<br/>so a single browser action is traceable end to end in Serilog / App Insights.
    end
